# Business-Administration Answering Guide

> The core asset of this project. It encodes the **answering format** that business-school markers reward, distilled from real UPM coursework and tutorial questions. Use it to: (1) label/quality-check training data, (2) prompt any LLM to produce format-correct drafts, and (3) verify model output.

---

## 1. Universal high-score rules

1. **Show all workings.** For any calculation: formula → substitution → result → interpretation. Never give only the final answer or percentage.
2. **Interpret every number in business terms.** After computing a ratio, say what it means for the owner/manager (e.g. "for every RM1 of revenue, RM0.60 remains after covering direct costs").
3. **Give an explicit judgement + evidence.** When asked "should X proceed", answer clearly (*should / should not*) with at least 3 data-backed reasons. Do not hedge.
4. **Use numbered structure in essays.** 1.0 Introduction → 2.0 Body → Case Study → Conclusion. Open the introduction with a definition.
5. **Cite authoritative local sources.** In a Malaysian context: MASB, Bank Negara Malaysia, Securities Commission Malaysia, Bursa Malaysia, IFRS, GRI. In-text (Author, Year) + Harvard-style reference list with URLs.
6. **Use concrete numbers to persuade.** Claims backed by figures (percentages, ratios, counts) read as evidence, not opinion.
7. **Respect format constraints.** Page limits (e.g. max 5 pages), minimum reference counts (e.g. at least five), submission platform, member list.
8. **Answer in English.** Use the exact terminology from the course materials.

## 2. Question-type templates

### 2.1 Definition questions ("Define X" / "What is X")
```
Definition (one sentence, using course terminology)
→ purpose or why it matters
→ one example
```
Example: "CVP analysis is a method that examines how varying levels of cost and volume affect operating profit. It helps managers plan production and pricing. Example: calculating the units needed to break even."

### 2.2 Distinguish questions ("Distinguish between X and Y")
```
Define each → list 2–3 difference points (each with an example) → one-line essence summary
```
Keep differences pairwise ("A is …, whereas B is …"), pair each point with an example, end with "therefore they suit different situations".

### 2.3 Explain / discuss questions ("Explain why…" / "Discuss FIVE…")
```
Direct answer + numbered points (1.2.3.4.5. …) → each point: one-line explanation + why it matters
```
If asked "Discuss FIVE assumptions", write exactly five numbered points, each with both meaning and significance. Use connectors (First, Moreover, Therefore).

### 2.4 Calculation questions ("Compute…" / "Calculate…" / "Prepare…")
Five fixed steps per sub-question:
```
① formula → ② substitute values (with units: RM / units / %) → ③ result (keep decimals) → ④ labelled answer → ⑤ one-line business interpretation
```
Example:
```
Gross Profit Margin = (Gross Profit ÷ Revenue) × 100%
= (150,000 ÷ 250,000) × 100% = 60%
→ For every RM1 of revenue, RM0.60 remains after covering direct costs.
```
- Keep the sub-question numbering from the brief (i/ii/iii or a/b/c).
- For schedule/table questions (cost classification, flexible budget, equivalent units), reproduce the table format with the same headers as required.

### 2.5 Case-analysis questions ("Case study" / "Financial health check")
```
① Calculations (as in 2.4) → ② item-by-item interpretation (number → business meaning)
→ ③ overall judgement (explicit + ≥3 reasons) → ④ extended analysis using course theory (Benefits / Risks / Mitigation)
```
- Lead with the judgement, then support with cited definitions and case-specific figures.

### 2.6 Essay questions (Accounting Part B / discussion papers)
```
Cover page → 1.0 Introduction (definition first + why it matters)
→ 2.0 Body (3–4 sections, incl. a Malaysian case) → 3.0 Conclusion (summary + outlook)
→ References (≥5, Harvard style + URLs)
```
Embed: in-text citations (Author, Year), concrete data, local perspective (e.g. Maybank / Bursa / NSRF).

## 3. Report skeleton (group assignments)

| Component | Requirement |
|---|---|
| Cover page | SCHOOL OF BUSINESS AND ECONOMICS / UNIVERSITY PUTRA MALAYSIA / course code & title / lecturer / GROUP X ASSIGNMENT / part name |
| Member list | Table: name + ID |
| Sections | Numbered headings following the brief's sub-questions |
| Essay structure | 1.0 / 2.0 / 3.0 numbering, definition-led introduction |
| Training-module style | Course Outline → Content (modules + sub-modules) → Methodologies → Task Analysis → Schedule (time table) → Roles → Materials → Evaluation Form (Kirkpatrick levels) |
| References | Harvard: Author. (Year). Title. URL |

## 4. Citation & authoritative sources

| Domain | Preferred sources |
|---|---|
| Accounting / Finance | MASB (MFRS), Bank Negara Malaysia, Securities Commission Malaysia, Bursa Malaysia, IFRS Foundation, GRI |
| HRM / Training | Kirkpatrick model, course textbook terminology |
| Franchising | IFA, disclosure regulations, real brand cases |
| Commercial Law | Case law (e.g. Donoghue v Stevenson), Malaysian statutes |
| Marketing / Brand | Kotler / Keller terminology, industry reports, local brand cases |
| Economics | Department of Statistics Malaysia, BNM annual reports, World Bank / IMF |

---

## 5. Pre-submission checklist

- [ ] Calculations: formula / substitution / answer / unit / interpretation all present? No "final percentage only"?
- [ ] Classification / schedule questions: headers match the brief? All cost categories covered?
- [ ] Case analysis: explicit judgement? ≥3 data-backed reasons?
- [ ] Essay: definition-led opening? numbered sections? Malaysian case? conclusion with outlook?
- [ ] References: count meets minimum? Harvard format? Every URL verified?
- [ ] Format constraints: page limit? member list / cover page?
- [ ] English throughout? Course terminology used?
- [ ] Presentation (if any): fits the time limit? Q&A prepared?

---

## 6. Known limitations

- LLMs (fine-tuned or not) can still miscalculate numbers or invent citations. **Human verification of numbers and references is always the final gate.**
- This guide encodes format conventions, not official grading rubrics.
